# BRAHMAGYAN — KRISHNA Deep Knowledge Architecture

BRAHMAGYAN is KRISHNA's permanent universal-learning and research intelligence. It is not a second control plane and does not run a permanent fleet of model processes.

## Authority

```text
KRISHNA
  |
SUDARSHAN
Permissions / Policy / Security
  |
BRAHMAGYAN
Deep research + knowledge maturation
  |
Gautama evidence review
  |
Veda Vyasa compilation
  |
Gyan-Bhandar proposal
  |
Owner approval / trusted storage
```

All model, browser, research, worker and external-tool execution still enters through Sudarshan's permissioned Action/Job architecture.

## Deep-learning rule

Reading is not learning.

The canonical loop is:

```text
Discover
→ Read
→ Understand Context
→ Extract Claims
→ Verify Sources
→ Cross-check
→ Find Contradictions
→ Apply
→ Test
→ Evaluate
→ Connect
→ Store
```

Knowledge maturity is strictly sequential:

- L0 — Discovered
- L1 — Read
- L2 — Understood
- L3 — Source Verified
- L4 — Cross-checked
- L5 — Applied
- L6 — Tested
- L7 — Mastered
- L8 — Connected with wider knowledge

A claim cannot skip a level.

### Evidence gates

L1 requires a traceable source.

L2 requires a context summary.

L3 requires a primary source when available (or an explicit reason it is unavailable) and Gautama review.

L4 requires independent cross-checking and Gautama review.

L5 requires application evidence.

L6 requires actual test evidence.

L7 requires synthesis plus teach-back.

L8 requires explicit wider-knowledge connections.

Trusted Gyan promotion requires at least L4, Gautama verification, Veda Vyasa compilation, strong evidence and no unresolved contradiction. Promotion still creates a Gyan-Bhandar approval proposal; BRAHMAGYAN does not silently write trusted facts.

## Modern science and Vedic/classical knowledge

When a mission reasonably connects both, BRAHMAGYAN requires distinct claim tracks.

Modern science may contain:

- peer-reviewed research;
- experimental data;
- replication;
- systematic review;
- current consensus and uncertainty.

Vedic/classical study may contain:

- original Sanskrit when available;
- critical editions;
- recognized commentaries;
- multiple translations;
- historical context.

Comparison happens only after both tracks are understood separately.

Allowed comparison labels include agreement, partial similarity, different conceptual framework, contradiction, symbolic/philosophical language, historically uncertain, not scientifically testable, modern evidence unavailable, or traditional claim unsupported by current evidence.

BRAHMAGYAN must never force a modern scientific discovery into an ancient verse because wording appears similar, and it must never present symbolic/philosophical material as experimentally demonstrated fact.

## Primary sources

Primary evidence has priority wherever practical.

Modern examples: original papers, datasets, clinical trials, official technical specifications, government records, standards, patents and official repositories.

Classical examples: original-language text, critical editions, recognized commentaries and historical scholarship.

Secondary summaries remain useful for discovery/context but do not inherit the evidentiary weight of the source they summarize.

## Contradiction memory

Contradicting evidence is never silently deleted.

A claim stores supporting, contradicting and qualifying evidence. Contradictions may later receive an explicit resolution, but the original contradictory source and resolution history remain attached to the claim.

## Temporal knowledge

Claims preserve first-seen, last-verified, valid-from, valid-until, previous-state, replaced-by, current-state, source history and knowledge version.

Superseding a claim preserves both the previous and current state.

## Provenance

Trusted proposals preserve claim ID, mission ID, researching Rishi, verification agent, compiler, knowledge track, maturity, evidence status, source identifiers, validity and version.

## Curiosity engine

Knowledge gaps may be queued with priority signals:

- relevance to KRISHNA;
- active project relevance;
- knowledge gap size;
- scientific importance;
- freshness;
- cross-domain usefulness;
- new discovery;
- security relevance;
- source availability;
- existing coverage;
- duplication;
- resource cost.

The queue is finite and prioritized.

## Background-learning resource rule

BRAHMAGYAN v1 does **not** start a background daemon.

A background-learning check is permitted only when production is not busy and resource thresholds are low. Current initial gate:

- CPU < 50%;
- RAM < 70%;
- no active production task.

If production becomes busy, research must checkpoint/release resources and resume later.

## Shishya workforce

Rishis may request temporary Shishya research teams through Sudarshan/AI-HR.

A BRAHMAGYAN Shishya batch is capped at 4 in v1.

Execution requires explicit owner/system approval. Shishya model calls still pass through Sudarshan.

Before retirement, the handover must preserve:

- verified findings;
- successful methods;
- failed approaches;
- corrections;
- reusable skills;
- evaluation results;
- research trajectory;
- sources;
- provenance;
- useful context;
- cross-domain relationships.

Workers are destroyed after the batch; knowledge remains.

## Research acquisition

Garuda owns source discovery/research scouting.

Garudanetra owns browser execution and source acquisition when interactive browsing is required.

A Garuda/Garudanetra result is candidate evidence. BRAHMAGYAN still has to extract claims, verify sources, cross-check and mature them.
