# KRISHNA OpenRouter Zero-Cost Fabric

## Purpose

KRISHNA may use OpenRouter only as a bounded cloud worker behind KRISHNA/Sudarshan
authority. Local Ollama remains the primary model path. The zero-cost fabric exists to
add temporary or specialist cloud capability without silently crossing into paid usage.

## Credential model

One enabled `free_only=true` gateway profile with base URL
`https://openrouter.ai/api/v1` is reused. Its API key remains inside KRISHNA's
Windows-DPAPI `SecureSecretVault`; adapters receive only the gateway profile ID and
call `ModelGatewayRegistry.request_json()`. Status/catalog APIs never expose plaintext
credentials.

Do not create one copy of the OpenRouter key for every model.

## Fail-closed zero-cost policy

Before every OpenRouter inference or image-generation execution KRISHNA refreshes the
live provider model catalog and requires the relevant numeric pricing fields to be
exactly zero.

KRISHNA refuses execution when:

- the model is no longer in the live catalog;
- the model is expired;
- required pricing is missing/opaque;
- any relevant reported price is non-zero;
- project privacy is `local_only` or `restricted`;
- the payload is explicitly marked sensitive;
- the prompt looks like it contains credentials/secrets;
- no eligible free provider succeeds.

Text/vision requests also send provider routing constraints:

- `allow_fallbacks: false`
- `data_collection: "deny"`
- `zdr: true`

If those constraints make the requested free model unavailable, KRISHNA tries another
eligible zero-cost model or returns to local inference. It does not relax the privacy
policy.

Paid cloud is disabled by default, even if a paid gateway/API key exists. An operator
must explicitly set `KRISHNA_ALLOW_PAID_CLOUD=1` for paid routing to become eligible.
Free-only requests never use that path.

## Role-based model selection

The live catalog is ranked dynamically rather than hard-coding a permanent free-model
list. Current role hints include:

- coding: Nex/Kimi/North Code/Laguna/DeepSeek/Qwen families;
- reasoning: Nemotron/DeepSeek/Kimi/Qwen/Ling;
- vision: Ling VL/vision/Inkling/Gemma/Omni;
- medical research: Ling Sante/medical/health;
- general: Kimi/Ling/Nemotron/DeepSeek/Qwen.

Explicit `:free` variants receive preference and models expiring within seven days are
strongly deprioritized. Availability and pricing remain provider truth, not KRISHNA
assumptions.

## Ming Image

The dedicated image adapter targets
`inclusionai/ming-image-0.1-design` only while the live catalog reports zero cost and
the OpenRouter Images API reports the model available.

KRISHNA sends:

- prompt;
- model;
- supported output format (PNG/JPEG/WebP).

KRISHNA does not send reference images, requested dimensions, or aspect-ratio controls
for Ming. Generated bytes are bounded and saved inside runtime state under
`.krishna_state/openrouter-free/images`.

Paid video, speech/transcription, image-editing or generation models are not wired into
the automatic free path.

## HTTP surfaces

Read-only/local status:

- `GET /api/openrouter/free/status`
- `GET /api/openrouter/free/catalog?refresh=1`
- `GET /api/openrouter/free/image?id=<uuid>`

Local governed execution:

- `POST /api/openrouter/free/complete`
- `POST /api/openrouter/free/image`

Execution also exists on the Shared Action Bus:

- `openrouter.free.complete`
- `openrouter.free.image`

## Privacy boundary

Private source code, credentials, raw HAWKEYE camera/audio evidence, personal/face data,
private Gyan-Bhandar material and other restricted information should remain local.
OpenRouter is intended for public/non-sensitive research, bounded cloud verification,
non-sensitive design generation and similar approved-cloud work.

Cloud model output is worker evidence, never KRISHNA authority and never automatic
Gyan truth. Verification and promotion remain separate.
