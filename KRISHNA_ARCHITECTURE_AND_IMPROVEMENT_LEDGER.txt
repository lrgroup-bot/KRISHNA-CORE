NON-NEGOTIABLE RULES
--------------------
1. Live KRISHNA is never a development workspace.
2. Every mutating engineering task uses an isolated candidate/worktree.
3. Research Shishya may search/read/analyse only; it cannot install/merge/promote.
4. A discovered repo/tool/model is NEVER trusted merely because it is popular.
5. Proposal must include source, license, maintenance/activity, security risk,
   privacy impact, resource cost, free/paid status, expected benefit, integration
   surface, alternatives, tests and rollback plan.
6. Zero-spend/local-first policy remains authoritative. No paid action without
   the owner's exact approval; existing hard zero-spend gates are not weakened.
7. OWNER approval is required before VISHWAKARMA implements a research proposal.
8. Frontend must be tested and shown before Windows EXE/package creation.
9. VISHWAKARMA cannot approve/promote its own work.
10. Independent verification + MRITYUNJAY regression/recovery check precede
    SUDARSHAN promotion.
11. Transactional backup + post-deploy health verification are mandatory.
12. Failed post-deploy verification => rollback to last-known-good.
13. Secrets/credentials never enter this ledger.
14. Every approved/deployed architecture change must append a CHANGE RECORD below.
15. MRITYUNJAY repairs toward the last VERIFIED architecture, not an unapproved idea.

24/7 RUNTIME
------------
Guardian -> START_KRISHNA -> verified runtime
  failure/event -> MRITYUNJAY -> diagnose -> isolated repair -> tests -> verify
                -> transactional promotion -> post-check -> keep or rollback

PLANNED IMPROVEMENT LOOP
------------------------
Research Shishya periodically searches authoritative web/GitHub sources
  -> evidence-backed PROPOSAL
  -> KRISHNA tells OWNER:
     "Today we found <X>. It provides <capabilities>. For KRISHNA it could
      improve <areas>. Risks/costs are <...>. Proposed integration is <...>."
  -> WAIT FOR OWNER APPROVAL
  -> if rejected: record REJECTED, no code change
  -> if approved: KRISHNA assigns VISHWAKARMA
  -> VISHWAKARMA creates isolated engineering mission/worktree
  -> implement -> tests -> security -> frontend proof
  -> OWNER frontend approval
  -> release candidate -> independent verification -> MRITYUNJAY check
  -> SUDARSHAN promotion -> transactional deploy -> health check
  -> append VERIFIED CHANGE RECORD here
  -> MRITYUNJAY can use record for future diagnosis/rollback/self-heal.
